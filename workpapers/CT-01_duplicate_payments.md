# CT-01 Duplicate payments

| Field | Detail |
|---|---|
| Test type | Key control test |
| Risk rating | High |
| Prepared | Generated by `audit_analytics.pipeline` on 2026-11-17 |
| Data | Synthetic accounts-payable ledger (not real company data) |

## Control objective
Each vendor invoice is paid only once.

## Risk
Cash leaves the bank twice for one obligation; recovery depends on the vendor's cooperation.

## Population
All 5,036 payments posted from 2025-01-01 to 2025-12-31 (CAD 53,939,358.33); full population, no sampling. Completeness checks: `outputs/completeness_checks.csv`.

## Procedure
For every vendor and amount, compare each payment with the previous one (window function). Flag the later payment when the invoice number matches or the two are within 30 days.

Query / code: [`sql/control_tests/01_duplicate_payments.sql`](../sql/control_tests/01_duplicate_payments.sql)

## Results

- Amount of flagged payments: CAD 101,975.67
- Known-answer check: 12 of 12 planted issues found, 0 missed. Other flags: 0 were planted issues of another type, 0 were clean records.

## Conclusion
Exceptions noted (12). In this synthetic scenario the control did not operate effectively for the flagged payments, pending follow-up.

## Follow-up procedure
Confirm with the vendor statement whether the second payment was a genuine second invoice; request a refund or credit note where it was not.

## Recommended management action
Add a hard stop in the payment system on vendor + invoice number + amount, and run this query before each payment run.
