# Data

## Synthetic accounts-payable ledger (`data/generated/`)
Generated by `python -m audit_analytics.generate_ledger --seed 2027`. Committed so results are reproducible
without running anything. All names (for example "Synthetic Vendor 012", "AP Clerk 3") are placeholders.

| File | Rows | Contents |
|---|---|---|
| `payments.csv` | 5,036 | payment_id, vendor_id, invoice_no, invoice_date, amount (CAD), currency, payment_method, created_by, approved_by, posted_at |
| `vendors.csv` | 157 | vendor_id, vendor_name, created_date, status, inactive_date |
| `employees.csv` | 20 | employee_id, employee_name, role, can_create, approval_limit |
| `planted_issues.csv` | 90 | payment_id, issue_type, group_id (answer key for validation) |

How it is built: 5,000 clean payments are drawn first (business days and hours, cents on every amount,
creator different from approver, amounts under 90% of the approver's limit, one payment per vendor per day). Then
a fixed number of issues of each type is planted, each by changing one attribute of a clean payment or adding a
new one. Counts per type are set in `PLANTED` in `generate_ledger.py`.

## IBM Transactions for Anti Money Laundering (`data/raw/`, not committed)
- Source: Kaggle, "IBM Transactions for Anti Money Laundering (AML)",
  https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml
- Synthetic financial transactions with an `Is Laundering` label.
- Download `HI-Small_Trans.csv` (requires a free Kaggle account) and save it as `data/raw/HI-Small_Trans.csv`.
- The file is not redistributed here. Check the licence on the Kaggle page before reusing it.

## Reference
- FINTRAC large cash transaction reporting: https://fintrac-canafe.canada.ca/ (the CAD 10,000 threshold
  informs the illustrative structuring and large-cash rules; this project does not reproduce FINTRAC guidance).
